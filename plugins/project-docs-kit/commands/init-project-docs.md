너는 프로젝트 초기 문서 스타터를 설치하는 작업을 수행한다. 아래 순서를 정확히 따른다.

## 0. 대상 디렉터리 결정
- 인자 `$ARGUMENTS`가 있으면 그 경로를 대상 루트로 쓴다.
- 없으면 `git rev-parse --show-toplevel`로 저장소 루트를 구한다. git 저장소가 아니면 현재 작업 디렉터리를 쓴다.
- 결정한 대상 루트를 한 줄로 알려준다.

## 1. 원본 템플릿 확인
템플릿 원본은 `${CLAUDE_PLUGIN_ROOT}/templates/project-docs/` 아래에 있다. 다음 7개 파일이다:

```
README.md
docs/product.md
docs/status.md
docs/runbook.md
docs/onboarding.md
docs/decisions/0001-record-architecture-decisions.md
docs/decisions/template.md
```

## 2. 충돌 검사 (덮어쓰기 금지)
대상 루트에서 위 상대경로별로 이미 파일이 있는지 확인한다.
- **이미 있으면 절대 덮어쓰지 않는다.** 그 파일은 "건너뜀"으로 분류한다.
- 특히 `README.md`는 대부분 이미 존재한다. 존재하면 건너뛰고, 사용자에게 "기존 README는 유지했고 참고용 스타터는 `docs/`에 있다"고 안내한다.

## 3. 복사
건너뛰지 않는 파일만 원본 내용 그대로 대상 경로에 만든다(하위 디렉터리 `docs/`, `docs/decisions/` 포함). 내용은 원본과 100% 동일해야 한다 — 이 단계에서는 값을 채우지 않는다.

복사 후 결과를 요약한다:
- 설치됨: <목록>
- 건너뜀(이미 존재): <목록>

## 4. 채우기 제안
복사한 파일에는 `<...>` 형태의 자리표시자와 `<YYYY-MM-DD>` 날짜가 들어 있다. 사용자에게 묻는다:

> "자리표시자를 지금 같이 채울까요? (프로젝트명·한 줄 소개·오늘 날짜 정도만 물어보고 나머지는 자리표시자로 둡니다.) 아니면 그대로 두고 직접 채우시겠어요?"

- **원하면**: 프로젝트명, 한 줄 소개, 오늘 날짜를 물어본 뒤 설치된 파일에서 해당 자리표시자(`<프로젝트명>`, 한 줄 소개, `<YYYY-MM-DD>` 등 파악 가능한 것)만 Edit로 채운다. 내용을 잘 모르는 자리표시자는 그대로 둔다 — 추측해서 채우지 않는다.
- **원치 않으면**: 그대로 두고, "각 문서 상단의 자리표시자를 채우면 된다"고 안내하고 종료한다.

## 주의
- 어떤 경우에도 기존 파일을 덮어쓰지 않는다.
- 대상이 git 저장소가 아니어도 동작해야 한다.
